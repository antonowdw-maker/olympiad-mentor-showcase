# Руководство пользователя — Olympiad Mentor

Личный тренажёр + ИИ-наставник для подготовки к школьным олимпиадам. Сейчас это математика, 6 класс; другие классы и предметы в планах.  
В демо-версии две темы, чётность и алгоритмы: по 8 статей, 23 и 21 задача.  
Несколько отдельных аккаунтов, прогресс у каждого свой.

> Пароли и логины живут только в локальном `.env` — **не** копируйте их в чаты и git.

---

## 1. Родителю: как поднять и не потерять данные

### Первый запуск

1. Скопируйте `.env.example` → `.env`, задайте `AUTH_SECRET` (см. «Аккаунты» ниже).
2. Опционально: `SEED_TEST_USER_*` — демо-пользователь; прогресс отдельный; **все темы оформления сразу открыты** (без порога 1000 кубков); кнопка **A** (эталон) — только у него.
3. В папке проекта:

```bash
npm install
npm run db:reset    # схема + демо-темы + пользователь из .env
npm run dev         # http://localhost:3000
```

4. Откройте `/login`, войдите логином из `.env`.

### Аккаунты

В `.env.example` задан демо-пользователь `SEED_TEST_USER_*`, только для локального запуска. У него все темы оформления открыты сразу и доступна кнопка **A** (эталон). Другие аккаунты создаются по тому же образцу в сиде.

### Обновление контента без сноса прогресса

```bash
npm run db:seed     # upsert статей/задач; Attempt не стирает
```

Полный сброс БД и прогресса — только `npm run db:reset` (осознанно).

### Сменить пароль

1. Поправьте `SEED_TEST_USER_PASSWORD` в `.env`.
2. Выполните **`npm run db:seed`** (не `db:reset`) — сид обновит хеш пароля, прогресс сохранится.

### Бэкап SQLite (REQ-QA-04+)

Автоматически (локально, не в git):
- при **`npm run dev`** — бэкап, если последнего нет или ему ≥ **24 ч**;
- перед **`npm run db:seed`** / **`db:reset`** — всегда свежий бэкап (seed ещё раз может сделать «if-stale»).

Хранится **2** последних копии в `backups/db/dev-YYYYMMDD-HHmmss.db` (+ `-wal`/`-shm`, если были).

Вручную: `npm run db:backup`.

Восстановление:
1. Остановите `npm run dev`.
2. Скопируйте нужный файл из `backups/db/` → `prisma/dev.db` (имя из `DATABASE_URL`).
3. При наличии рядом `…-wal` / `…-shm` — тоже подставьте с теми же суффиксами к `dev.db`.
4. `npm run dev`.

Если `prisma/dev.db` ещё нет (чистый клон) — `db:backup` / хуки на `dev`·`seed`·`reset` **не падают**: бэкап просто пропускается до первого появления файла.

Секреты (`.env`) бэкапьте отдельно и тоже **не** в git.

### Наставник (ИИ)

Без `GEMINI_API_KEY` и без `DEEPSEEK_API_KEY` приложение работает: подсказки из контента (fallback).
С ключом Gemini — живой диалог **у задачи** и **на странице темы**. Модель: `GEMINI_MODEL` (рекомендуем **gemini-3.5-flash**; `gemini-3.6-flash` часто не успевает и показывает «Наставник (без ИИ)»). Таймаут — `GEMINI_TIMEOUT_MS` (ориентир 60 с).
Опционально второй ключ `DEEPSEEK_API_KEY` (модель `DEEPSEEK_MODEL`, дефолт **deepseek-v4-flash**): если Gemini недоступен (нет ключа / 429 / timeout / сбой), наставник тихо пробует DeepSeek, затем снова fallback без ИИ. Имя провайдера ученику не показывается.
При перегрузке (503/429) или снятой модели (404) Gemini сначала пробует запасные модели `GEMINI_FALLBACK_MODELS` (дефолт: 3.5-flash-lite → 3-flash-preview → 3.6-flash → 3.1-flash-lite, по одной попытке).
Если серверу нужен исходящий прокси, задай в `.env` `OUTBOUND_HTTPS_PROXY=http://127.0.0.1:<порт>` и перезапусти `npm run dev`. Порт проверяется при старте: если он закрыт, запросы идут напрямую.

## 2. Ученику: как заниматься

### План на день

1. На главной — вкладки **«Что сегодня»** (дефолт) | **«Собрать обучение»** | **«Темы»**. В «Что сегодня» — тизер плана → **«Открыть план»** (или сразу `/plan`). Смена темы в тизере **не** уводит на план. Собрать пакет вручную — вкладка «Собрать обучение» (или с `/plan` ссылка «Собрать на главной»). В шапке — **кубки** и **ур./ранг**; слева — меню **класс (6…11) → предмет → темы** (изначально все ветки свёрнуты, после перезагрузки — снова свёрнуты; на ПК — hover; на телефоне — кнопка у бренда; пустые — «Пока пусто»; **5 класс не показываем**; внизу меню — **«Статистика»**, **«Источники»** и **«Выйти»**); ниже вкладок — блок **«Оформление»** (Классика / Игровая / Дорама / Бравл) и свёртка **бейджей**.
2. **Тема плана** — выпадающий список: одна тема **или** **«Разные темы»** (если открыты ≥2) **или** **«Собранное обучение»** (пакеты из формы «Собрать обучение»). Выбор запоминается **в этом браузере** (при «Выйти» сбрасывается). История пакетов — **отдельно** по каждой теме, для «Разные» и для «Собранное».
3. Вкладка **«Текущий»** — список на сегодня: до **6 задач** (ориентир ~1 час) + статьи. У задач в плане видны **минуты** (2 / 6 / 12) и **грейд** (низкий / средний / высокий) — это олимпиадная сложность, **не** класс «5–6». В режиме «Разные» / «Собранное» задачи могут быть из разных тем. Когда **все задачи пакета решены**, появится **«Закрепить пройденный материал»**: короткий тест по другим вариантам тех же задач (одна попытка, без подсказок и наставника). **«Позже»** только откладывает кнопку (без сессии и без награды). **«Прервать»** внутри теста закрывает закрепление по этому списку навсегда — повторно открыть нельзя, награды нет. **+10 кубков** и бейдж «Материал закреплён» — если тест **сдан** (~70% баллов с весом грейда: низкий 1 / средний 2 / высокий 3); иначе завершение без награды.
4. Решай задачи **верным ответом**. Кнопка **A** («покажи решение») сама задачу **не** закрывает.
5. Когда все задачи текущего списка решены — можно нажать **«Новый список»**.
6. Вкладка **«История»** — предыдущие списки за сегодня в выбранном режиме. Если открыл задачу из истории, **«← К плану»** вернёт на ту же вкладку.

Если написано **«Тема закрыта»** / **«На сегодня всё»** — новых задач в этом режиме нет: **смени тему** (или выбери одну тему вместо «Разные»), повтори статьи или решай свободно через **Темы** на главной.

### Обновление БД (если план дня был до 10c)

1. Скопируй `prisma/dev.db` в backup.  
2. `npm run db:backfill-plan-scope` — заполнит `scopeKey` **до** смены unique.  
3. `npx prisma db push`.  
4. Повторный `npm run db:backfill-plan-scope` должен показать `left empty: 0`.

На новой БД достаточно обычного `npm run db:reset` / `db:push` + seed.

### Обновление БД (чат наставника: topic-сессии)

Если БД создана до follow-up B+C (колонка `MentorSession.scopeKey`):

1. Backup `prisma/dev.db`.  
2. `npm run db:backfill-mentor-scope` — заполнит `task:` / `topic:` scopeKey и схлопнет дубликаты.  
3. `npx prisma db push`.  
4. Повторный backfill → `left empty: 0`.

### Тема и задачи без плана

На главной вкладка **«Темы»** — выпадающий список для перехода и карточки со прогрессом (глобального ряда тем под шапкой нет). Когда решены **все** задачи темы — статус **«Тема пройдена»** (на карточке, на странице темы и галочка в левом меню). Это не то же самое, что сдача теста закрепления (~70% баллов). Можно читать статьи и решать задачи вне плана; прогресс всё равно считается. У задачи рядом с «ур. класса» — бейдж грейда. Вверху страницы задачи — ссылка с **названием темы** (например «← Чётность»), а не голое «К теме». Между задачами и **между статьями** одной темы — ссылки «предыдущая / следующая» внизу страницы. У части задач есть кнопка **«Другой вариант»** (новые числа/формулировка, **без** доп. кубков): она **появляется только после верного ответа** на текущий вариант — и в первый раз, и после каждой смены. План дня предпочитает задачи, у которых ещё есть нерешённый вариант условия. Чат наставника относится к **текущему** варианту. Блок **«Решение этой задачи (A)»** — только у тестового аккаунта `SEED_TEST_USER` (ученик); у остальных кнопки A нет.

### Задачи с ответом-таблицей

В некоторых логических задачах («кто сколько лет, чей питомец, во сколько репетиция…») вместо поля ввода — **таблица**: строки — участники, столбцы — признаки. В каждой ячейке выбери значение из выпадающего списка (сначала везде «—»). Значения в списках идут в порядке условия, а не в порядке ответа — подсказки в таблице нет. Заполни **все** ячейки и нажми **«Проверить»**: если что-то пропущено, появится «Заполни все ячейки таблицы», и попытка **не засчитывается**. Результат — «верно» или «неверно» целиком (какая ячейка ошибочна, не показываем). На телефоне таблица превращается в карточки по одной на участника.

Справа от кнопки «Проверить» (на широком экране) — напоминание: «Решить задачу — это не угадать ответ! Объяснить решение — это не только дать ответ…». Ответ проверяется автоматически, но рассуждение стоит проговорить или записать.

### Кубки и бейджи

В шапке видно накопленные **кубки** (= внутренний XP 1:1) и **ур./ранг**. Страница `/stats` — из левого меню (**«Статистика»** над «Выйти»). Бейджи — на главной в свёртке «Бейджи» (на Классике/Игровой/Дораме — круглые «учёные»; в Бравле — game-рамки с иконкой). Наведи или сфокусируй значок — стилизованная подсказка (название и факт; не уезжает за край экрана). Кубки даются только за **первое** верное решение задачи: база зависит от грейда; за открытые подсказки и неверные попытки снимается по 10% (не меньше 10% базы, баллы вверх). Повтор и «Другой вариант» очков не дают. Бейджи — за число разных решённых задач и за «приёмы» темы; в MVP бейджи **не снимаются** при пересчёте.

### Оформление

На главной блок **«Оформление»**: четыре пресета (**Классика**, **Игровая**, **Дорама**, **Бравл**). **Классика** и **Игровая** — всегда. **Дорама**, **Бравл** и любые будущие неординарные темы — с **1000 кубков**. Исключение: тестовый аккаунт `SEED_TEST_USER_*` (обычно **ученик** / демо-пользователя) — все темы сразу открыты. «Дорама» — romantic CSS (ключ в БД `soft`). Везде в UI — **кубки** + уровень/ранг. Уровень = floor(кубков/100). Бейджи меняют вид; названия/факты едины.

### Статистика и источники

Страница **`/stats`** (левое меню → «Статистика»):
- сводка: кубки, число решённых задач, дни с попытками, число закреплений с наградой;
- блок **«Закрепления»**: завершённые тесты — тема (или «Разные» / «Собранное»), номер списка, сдано/нет, **время** (wall-clock с входа до последнего ответа);
- таблица **по темам**: прогресс %, число неверных попыток, сколько задач смотрели эталон (A), оценка минут (сумма 2/6/12 по решённым — не секундомер);
- блок **«Рейтинг»**: рейтинг всех аккаунтов по кубкам (при равенстве — по числу решённых задач).

Страница **`/sources`** (левое меню → «Источники», под «Статистика»): MathUs / олимпиады, трекер покрытия фазы 6 (счётчики видны сразу, таблица свёрнута — «Показать таблицу трекера»), маппинг разделов → темы. PDF в git не кладём.

После обновления схемы с уже накопленными Attempt (без полного `db:reset`):

```bash
# 1. Бэкап prisma/dev.db
npx prisma db push
npm run db:backfill-xp
```

### Черновики изоморфов (12b, для автора контента)

Не для ученика. Opt-in Gemini готовит варианты условия в файл на review:

```bash
npm run content:draft-instances -- --task=t1-pvg19-knights-count --write
# без ключа / офлайн:
npm run content:draft-instances -- --task=t1-bel20-squirrel-colors --write
```

Результат: `content/drafts/<slug>.instances.json` (не в git). В сид переносить вручную после проверки эталонов.

### Подсказки и наставник

- На задаче открываются **ступени подсказок** по одной (сервер помнит, что уже открыто).
- **Наставник** — чат рядом с задачей и на странице темы: наводящие вопросы, ссылки на ваши статьи, без спойлера ответа.
- После многих сообщений к ИИ на одну задачу сработает мягкий лимит (`MENTOR_LLM_MAX_TURNS` в `.env`, обычно ~30): дальше — обычные подсказки **без** вызова ИИ. Это не поломка, а ограничение.
- Кнопка **A** — явное «покажи решение этой задачи» (эталон).

## 3. Короткий smoke (для родителя / после обновления)

На поднятом `npm run dev`, под семейным или тестовым (`SEED_TEST_USER_*`) аккаунтом:

1. [ ] Логин работает  
2. [ ] Home → вкладка «Что сегодня» (дефолт) → план → `/plan`; `/?home=gather` — собрать; с `/plan` ссылка «Собрать на главной»; смена темы в тизере **не** уводит на `/plan`  
3. [ ] Вкладка «Темы»: выпадающий список Логика…Игры + карточки; переход на `/topics/t7-games` (ряда под шапкой нет)  
4. [ ] Задача: видны «ур.» и «грейд»; неверный и верный ответ, прогресс меняется; при первом верном — +кубки в сообщении / шапке  
4a. [ ] В шапке кубки + ур./ранг; «Статистика» и «Выйти» — в левом меню; на главной «Оформление» (Дорама/Бравл с 1000 кубков; замок если меньше; у демо-пользователя — всё открыто) и бейджи в свёртке (вид зависит от темы)  
4a′. [ ] Кнопка A («Решение этой задачи») есть только у демо-пользователя; у остальных — нет  
4b. [ ] `/stats`: на телефоне — карточки по темам; на ПК — таблица; блок «Рейтинг» (у «ты» кубки читаются во всех темах)  
4c. [ ] DevTools **375px** (или телефон): шапка — кубки/уровень (без «Меню»); кнопка тем у бренда → drawer; нет горизонтального скролла на `/` и задаче; кнопки «Проверить» / вкладки удобно нажимать  
4d. [ ] Desktop: левое меню — класс (6…11) → предмет → темы; **без 5 кл.**; пустые «Пока пусто»; при загрузке все ветки свёрнуты; hover поверх (без прыжка); sticky; внизу «Статистика», «Источники», «Выйти»
5. [ ] В плане у задач минуты не все по 12; задач в пакете ≤ 6  
6. [ ] Открывается следующая ступень подсказки  
7. [ ] Наставник отвечает (с ключом) **или** понятный fallback без ключа  
8. [ ] Кнопка A: у демо-пользователя показывает эталон; у остальных блока нет  
9. [ ] «Новый список» неактивна, пока текущий список не закрыт верными ответами  
10. [ ] Обновление `/plan` (F5) **не** меняет состав текущего списка  
11. [ ] Второй аккаунт: свой прогресс / свой план, чужие решения не видны  

Если что-то из этого красное — лучше не объявлять «готово к ежедневным занятиям», пока не почините.
