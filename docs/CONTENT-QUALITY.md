# Качество контента — Olympiad Mentor

> Документ витрины. Полный банк, трекер `content/sources/`, решатели `lib/content/audit/`, отчёты и локальные материалы (`docs/audit/`, `docs/doc/`, `tmp-*`, `docs/REVIEW*`) находятся в приватном репозитории; упоминания этих путей описывают его.

Как задачи попадают в банк и почему их ответам можно доверять. Роли и промпты проверяющих — [`ai-workflow/README.md`](ai-workflow/README.md).

## 1. Как устроена проверка

Полный банк: 707 задач (канонов), у каждой 3 варианта. В витрине — 44 задачи, собственные и классические. Для каждого пакета задач:

1. **Источник.** Условие берётся дословно, ответ — сначала из официального решения организаторов; файл фиксируется путём и sha256.
2. **Решатель.** Код независимо пересчитывает эталон каждого варианта по его условию; результат и выкладки попадают в proofs.
3. **Автопроверки.** Валидатор и тесты ловят вырожденные варианты, совпадающие ответы и утечку ответа в подсказках.
4. **V1-text.** Другая LLM без доступа к файлам проверяет арифметику, согласованность и формулировки по отчёту.
5. **V2-files.** Ещё одна LLM, только чтение, сверяет сиды с источниками, решатели, рисунки, трекер и БД.

Покрытие источников отслеживает `content/sources/coverage-m6.json` и страница `/sources`.

**Права.** Тексты олимпиадных задач принадлежат их авторам и организаторам олимпиад, поэтому в открытый репозиторий они не входят. Реестр §2 фиксирует происхождение задач полного банка и не является юридическим заключением.

### 2.1 Где искать официальные ответы и решения (сверка эталонов)

Задачник MathUs даёт условия без решений. Для каждой задачи пакета: найти олимпиаду-первоисточник (год, этап, класс, номер) → официальное решение → сверить эталон; если решения нет — полный перебор / независимый пересчёт. В `REVIEW-REQUEST-*` указывать, какой источник сверен.

**Порядок поиска (правило владельца 2026-10-07).** Нельзя сразу открывать таблицу сайтов ниже. Шаги без пропуска:

1. `docs/doc/materiali/` — материалы владельца (опись в локальная опись). Обязательно: `решения математика/**` (включая `math510keys` и копии «(1)»); три zip в `docs/doc/`; `математика доп/`.
2. `tmp-olymp6/` — уже скачанный корпус: `pdf/`, `txt/`, `index.txt`. Искать по фрагменту условия. **`answers-map.txt` не доказательство отсутствия ответа** — сначала открыть сам листок (на 2026-10-10 карта помечает ответы у 12 из 191, хотя многие листки печатают ответ под задачей).
3. Сайты из таблицы — **только если** шаги 1–2 не дали оригинал или офиц. решение **и** у канона `risk !== linear` (playbook [C], AC T8d+). Одна попытка 30–60 с, при обрыве не догонять. Скачанное — в `tmp-<пакет>/` (не в `tmp-olymp6`). Журнал — поле `searchLog` в `T*_SRC`. Статус `"не проверялась — линейный канон"` только при `risk = linear`. Формулировка «решения не публикуются» запрещена.

**Столбец «Примеры использованных файлов»** — только **конкретные URL, по которым файл реально скачан**. Не выдумывать URL-шаблоны (`…/<год>/…-sol.pdf`) как будто файл скачан. Колонка «Где искать» — сайт архива, не доказательство скачивания.

## 4. Качество каждой задачи

- Условие как в источнике (орфография / markdown ок).  
- **Канон — дословно по источнику** (правило владельца, 2026-09-27), если это возможно; допустимо только дописать строку о формате ответа или взять один пункт многопунктной задачи (с пометкой). `sourceHint` таких канонов — «· дословно · офиц. решение: <где> ·» вместо «близкий перенос».

## 6. Политика наполнения банка

1. Волна = тема: эталон + ≥3 подсказки + `sourceHint` + валидация.  
2. **Фаза A (набор темы / MathUs-6):** канон **дословно** по источнику (допустима строка формата ответа); эталон — сначала по официальному решению (§2.1); PDF/DOCX не в git. Цель фазы 6 — **100% задач** из реестра. Слайс **≤10 канонов**.  
3. **Фаза B (рост банка):** изоморфы / свои формулировки (агент / итерация 12); слайс **P-VOLUME** после `M6-DONE`.  
4. **P-AUDIT-INSTANCES** — сверка эталонов всех вариантов T1…T9 (решатели + V1-text + V2-files).  
5. Пагинация — итерация 10 (с T2).  
6. Без эталона в боевой сид не класть.  
7. **Закрепляющая** (`similarTaskSlug`) **не сложнее** исходной по `grade` — иначе `warn SIMILAR_HARDER`.  
8. **`db:seed` = upsert** контента **без** сноса Attempt/чата. Удаление «хвостов» slug — только явно (`SEED_PRUNE=1`). Разовый сброс прогресса после hotfix эталонов — `scripts/reset-hotfix-attempts.ts`, не в обычном сиде.

**Размер слайса импорта:** **≤10 канонов** за слайс / PR (каждый ×3 варианта). Больше 15 уже плохо контролируются и при написании, и при ревью; крупный раздел источника дробить на части (a/b).
