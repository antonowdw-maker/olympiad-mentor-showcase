## 1. Продукт

| Параметр | Решение |
|----------|---------|
| Пользователь | Сейчас ученик 6 класса; задел под другие классы |
| Цель | Развитие мышления, неординарные задачи → олимпиады → в перспективе поступление без ЕГЭ |
| Предмет (MVP) | Математика |
| Тема (MVP) | **T1** — логика и рассуждения |
| Формат | **Гибрид**: тренажёр + прогресс + доки + ИИ-наставник |
| MVP-стратегия | **A** — одна тема + доки + наставник |
| Вовлечение | **L0** — чистый UI, прогресс % (стрик — опционально, не раздувать) |
| Роль ИИ | **I1** — наставник в чате; задачи из базы (генерация — позже) |
| Контент | Открытые архивы/приёмы + позже ИИ в черновики с проверкой |
| Педагогика | Не спойлерить ответ; вести к решению; ссылки на **внутреннюю** документацию |
| Тон | Строгий коуч / спокойный ментор |
| Платформа | Сначала ПК; аккаунт; UI на русском (+ задел i18n/EN) |
| Ритм | ~1 час в день |
| Стек | Бесплатный и **долгоживущий** (не короткий триал) |
| Масштаб | Небольшая группа пользователей → возможность роста |

### Принципы

1. Итеративно: варианты → выбор человека → реализация слайса.
2. Системные требования (не бизнес-маркетинг); могут уточняться в ходе MVP.
3. **Unit-тесты обязательны** в слайсах с кодом; ориентир coverage **~85%**.
4. **Ручные и авто ТК** — только **после MVP** (когда контракты стабильнее).
5. Не подгонять требования под test-case-assistant; формат можно держать близким «на будущее».
6. Shift-left тестирование помним; системно — после MVP.
7. Комментарии в коде — **подробно на русском**.
8. Необходимая документация обновляется вместе с коммитом, пушем и мержем.
9. Коммит / пуш / мерж — только по явной команде («коммит», «пуш», «мерж»).

Подробности — [`ENGINEERING-PROCESS.md`](ENGINEERING-PROCESS.md).
