## 1. Назначение системы

Веб-приложение для **ученика**: изучение олимпиадной математики через внутренние статьи, задачи с проверкой ответа и **ИИ-наставника**, который ведёт к решению без спойлера эталона (кроме явных действий ученика по политике ниже).

MVP: стратегия **A + L0 + L1 + I1**, тема **T1** (логика и рассуждения), UI на русском, ПК first. Банк T1…T7 в runtime.

### 3.5a UserBadge + XP (L1 / iter 11)

| Поле / код | Смысл |
|------------|--------|
| User.totalXp | Сумма XP |
| TaskXpAward | Факт начисления за задачу; `@@unique([userId, taskId])` |
| UserBadge.code | `debut` \| `steady` \| `deep` \| `technique:<topicSlug>` |
| UserBadge.title | Человекочитаемый заголовок |
| UserBadge.earnedAt | Когда выдан |

**REQ-L1-01.** XP только за **первое** верное по канону (`TaskXpAward`): база `low` **10** / `mid` **20** / `high` **35**. Штраф **−10%** за каждую открытую ступень подсказки и за каждую неверную попытку до верного; итог не ниже **10%** базы; баллы целые (**ceil**). Повторные верные / другие изоморфы — **0**.  
**REQ-L1-02.** Milestone-бейджи по числу **уникальных** верных задач: `debut` (≥1), `steady` (≥10), `deep` (≥25).  
**REQ-L1-03.** Бейдж приёмов темы `technique:<topicSlug>` — при ≥**5** уникальных верных в этой теме.  
**REQ-L1-04.** UI: **кубки** в шапке (= `totalXp` 1:1); бейджи на главной (**свёртка**, не конкурируют с планом); визуал зависит от темы (круги «учёных» / brawl-рамки); по hover/focus — стилизованная подсказка (`position: fixed`, clamp к viewport; без native `title`); опционально краткий фидбек (+кубки / новый бейдж) после верного ответа. Коды и пороги наград не меняются (REQ-L1-02/03).

**REQ-UI-THEME-01.** У авторизованного User пресеты: `default` («Классика»), `arcade` («Игровая»), `soft` («Дорама»), `brawl` («Бравл»), поле `User.uiTheme`. Алиас формы `dorama` → `soft`. Гость — `default`.

**REQ-UI-THEME-02.** Неординарные темы (`soft` / «Дорама», `brawl` / «Бравл» и любые будущие вне ordinary) разблокируются при `totalXp ≥ THEME_PREMIUM_UNLOCK_CUPS` (**1000**). Ordinary: `default`, `arcade` — всегда. До порога в пикере disabled; запись через action отклоняется; если в БД locked-тема без порога — оболочка показывает `default`. **Исключение:** User с `login === SEED_TEST_USER_LOGIN` (тестовый «ученик») — bypass: все темы открыты без порога (пикер, action, resolveEffective). В UI накопленный XP везде показывается как **кубки** (1:1).

**REQ-UI-THEME-03.** Визуал бейджей зависит от активного `uiTheme`; `title` / факт / учёный из каталога **едины** на всех темах. Коды и пороги выдачи L1 не меняются.

**REQ-UI-THEME-04.** Единая шкала **уровня** для всех тем: `level = floor(totalXp / 100)` (0 при 0…99, 1 при 100…199, …). По уровню — **ранг** (Новичок → … → Легенда / Легенда II…). В шапке везде: кубки + ур./ранг (на `brawl` — thickened HUD).

**REQ-UI-NAV-01.** Левое меню: вложенность **класс (6…11) → предмет (математика / русский / литература / история / физика / химия / английский) → темы**. Клик по теме → `/topics/[slug]`. Пустые слоты показывают «Пока пусто» (сейчас контент только у математики **6**; метка темы `5-6` показывается в слоте 6; пункт **5 класс в меню нет** — банк 5 кл. не расширяем). Desktop (`md+`): узкий рельс фиксированной ширины в потоке; раскрытие по hover **поверх** контента (без layout shift); `position: sticky; top: 0` (меню не уезжает при длинном скролле; не `fixed` на весь viewport). Mobile: drawer по кнопке у бренда; тач ≥44px. Сверху — ник и кубки (если вошёл) и опц. общий % банка; внизу — **«Статистика»** → **«Источники»** → «Выйти» (гость: «Источники» / «Войти»). Шапка: только кубки + ур./ранг (гость — «Войти»); без disclosure «Меню». Вкладки UX-HOME не убираются.

**REQ-L1-05.** Идемпотентность XP — по `TaskXpAward` `@@unique([userId, taskId])`: create факта + `increment totalXp` в одной транзакции; конфликт unique → 0 XP. Бейджи — `@@unique([userId, code])`; в MVP бейджи **необратимы** (backfill только upsert, orphan не удаляет). Attempt можно пересчитать скриптом `db:backfill-xp` (rebuild фактов XP).

### 3.5b TaskInstance (iter 12a)

| Поле | Смысл |
|------|--------|
| TaskInstance | Изоморф канона: statement / acceptedAnswers / hintSteps / options |
| UserTaskInstanceShow | Показ user×instance (+ openedCount подсказок); анти-повтор |
| Attempt.taskInstanceId | С каким instance сверяли (опц.) |

**REQ-INST-01.** Канон `Task` может иметь пул `TaskInstance` (≥3 в сиде, если задан).  
**REQ-INST-02.** Текущий вариант **липкий** при «Проверить» / обновлении страницы. Новый изоморф — по кнопке **«Другой вариант»** при пуле ≥2 (серверная проверка). **P-VARIANT-AFTER-CORRECT** (заменяет P-VARIANT-ONCE): кнопка **не отображается**, пока нет верного Attempt на **текущем** instance — и на первом визите, и после каждой смены; появляется сразу после верного ответа. Сервер отклоняет смену без верного на текущем. При исчерпании пула — цикл по `order`. Доп. XP за другие варианты **нет** (начисление по канону `taskId`, REQ-L1-01).

**REQ-PLN-08 (P-PLAN-UNSOLVED).** В план дня / gather / mixed в набор попадают каноны, у которых есть instance **без** верного Attempt. Канон со всеми instance решёнными в набор не берётся (тема `theme_closed` при полном исчерпании). Открытие задачи предпочитает нерешённый instance. Завершённость пункта текущего пакета — верный Attempt **после** `createdAt` пакета (не старый верный на другом instance).  
**REQ-INST-03.** Проверка ответа, подсказки, кнопка **A** и наставник — по **текущему** sticky instance; клиентский `instanceId` сверяется с серверным binding (чужой/устаревший/пустой при пуле — отказ). XP/прогресс «решено» — на уровне канона (`taskId`).  
**REQ-INST-04.** Публичный DTO без эталона; `instanceId` можно отдавать клиенту для submit/hints.  
**REQ-INST-05.** Reveal (`TaskInstanceReveal`) и история mentor (`scopeKey` `task:<id>:inst:<instanceId>`) — **на instance**; другой вариант — отдельная тренировка. Без пула — прежние `TaskReveal` / `task:<taskId>`.  
**REQ-INST-06.** Штраф XP за неверные попытки **не** считает Attempt с `solutionRevealed=true` (кнопка A).  
**REQ-INST-07 (12b).** Черновики изоморфов — **offline** CLI (`content:draft-instances`): opt-in Gemini → JSON → Zod/validate → `content/drafts/` для ручного review; **не** live-генерация на клик ученика; в сид только после человека.

### 3.6 HintPolicy (хранение в MVP)

**Один способ для MVP:** ступени подсказок — в контенте задачи (`hintSteps`); пороги и правила — в коде/конфиге (не три параллельных хранилища).

| Параметр (конфиг) | Default MVP | Смысл |
|-------------------|-------------|--------|
| wrongAttemptsBeforeBoost | **3** | После N неверных Attempt — усиление помощи (**не** авто-эталон) |
| reinforceAfterHintSteps | **3** | Если верно при открытых ≥3 ступенях → закрепляющая задача |
| allowExactRevealButton | **true** | Кнопка A: эталон этой задачи |
| allowSimilarWorkedExampleButton | **true** | Кнопка B: похожий разбор |

**REQ-TRN-01.** До/без LLM ученик получает ступенчатые подсказки из `hintSteps`.  
**REQ-TRN-02.** Текст ступени **не** содержит дословно ни один из `acceptedAnswers` (проверка валидацией контента).  
**REQ-TRN-03.** После **3** неверных попыток система **не** показывает эталон автоматически. Она усиливает помощь: ссылки на связанные DocArticle и/или следующую доступную ступень подсказки; тон — «загляни в тему и попробуй ещё».  
**REQ-TRN-08.** Кнопка **B** «Похожий пример с разбором» — показывает `workedExample` / разбор задачи по `similarTaskSlug`, **без** выдачи `acceptedAnswers` текущей задачи.  
**REQ-TRN-09.** Кнопка **A** «Покажи решение этой задачи» — единственный путь автопоказа эталона текущей задачи; выставляется `solutionRevealed`; сервер проверяет право (сессия) и отдаёт эталон только после явного запроса. **В UI и action кнопка A доступна только** User с `login === SEED_TEST_USER_LOGIN` (тестовый «ученик»); у остальных блока нет, action отклоняется.  
**REQ-TRN-10.** После **верного** ответа, если `hintsOpenedCount ≥ 3`, система предлагает **закрепляющую** похожую задачу (`similarTaskSlug`). Лимит подсказок **0 или максимум 1 ступень** действует **только** на визите по этому предложению (маркер `?reinforce=1`); обычный вход на ту же задачу сохраняет полный потолок ступеней.

### 3.7 MentorSession / MentorMessage

| Поле | Смысл |
|------|--------|
| session: userId, taskId?, topicId? | Контекст чата |
| messages: role, body, createdAt, mode | `mode`: `llm` \| `fallback` — **на сообщении** (квота может кончиться mid-chat) |

**REQ-MNT-01.** Чат наставника доступен в контексте задачи и/или темы.  
**REQ-MNT-02.** Режим по умолчанию — сократический: наводящие вопросы, ссылки на DocArticle; **не** выдаёт эталон.  
**REQ-MNT-03.** Эталон текущей задачи через наставника — только если сервер уже разрешил reveal по кнопке A (иначе мягкий отказ: наводящий вопрос / «попробуй ещё, ответ сам»).  
**REQ-MNT-04.** При отсутствии ключа, отключённом LLM, таймауте (**60 с** по умолчанию, значение из env), ошибке 4xx/5xx, исчерпанной квоте (429) или мягком лимите сообщений на задачу (**NFR-10**) наставник переходит в `mode=fallback`: ступенчатые подсказки из контента + понятное сообщение. Приложение остаётся работоспособным.  
**REQ-MNT-05.** Вызов Gemini только server-side; ключ не на клиенте.

### 3.8 DayPlan (итерация 6)

| Поле | Смысл |
|------|--------|
| DayPlanPackage: userId, scopeKey, date, seq | Один **пакет** в истории дня; `scopeKey` = `topic:<slug>` или `mixed`; `date` = календарный день (`Europe/Moscow`); `seq` 1…n; `topicId` — якорная тема (FK) |
| items | `{ kind: 'article' \| 'task', slug, title, estMinutes, topicSlug, grade? }[]` (JSON) |

**REQ-PLN-01.** Система предлагает простой план на день по **выбранной области**: одна тема банка **или** режим **«Разные темы»** (`mixed`). Новый выбор `mixed` в пикере — только при ≥2 открытых темах; уже выбранный `mixed` (cookie / `?topic=mixed`) остаётся валидным для просмотра истории даже при <2 открытых. Тизер на `/`, полный UI на `/plan` (вкладки «Текущий» / «История»). Выбор запоминается в cookie браузера (`om_plan_topic`, сброс при выходе; значение — slug темы или `mixed`); дефолт — первая тема с нерешёнными задачами (`totalTasks > 0` и не все решены). Пакеты разделены по `scopeKey` (история одной темы не смешивается с `mixed`). Якорный `topicId` у mixed — технический FK (темы банка в MVP не удаляем).  
**REQ-PLN-02.** В пакет не включаются задачи с верным Attempt и задачи, уже попавшие в пакеты **этого** дня **в той же области** (`scopeKey`). Пакет-повторение (`theme_closed` / `caught_up`, статьи) создаётся только когда **все предложенные за день** задачи решены (или тема/пул полностью закрыт); преждевременный `caught_up` при нерешённых в пакетах дня **не** оставляем. Кнопка «Новый список» при review **неактивна**.  
**REQ-PLN-03.** Пакет **сохраняется** в БД; обновление страницы не пересобирает список. **Материализация при просмотре:** первый GET `/` или `/plan` за календарный день (для выбранной области) создаёт пакет, если его ещё нет — в т.ч. review при закрытой теме (PT-07; осознанное поведение, не «тихая» пересборка).  
**REQ-PLN-04.** «Текущий» список = первый за день **normal**-пакет с ещё нерешённой задачей (иначе — последний review / последний с задачами). Кнопка «Новый список» создаёт новый пакет только если все **задачи текущего** списка решены (статьи не блокируют) и есть доступные задачи; иначе отказ / кнопка неактивна. История на `/plan`.  
**REQ-PLN-05.** Ориентир объёма пакета ~**60 мин** (стремимся набрать, если банк позволяет); верхнего лимита минут **в день** нет (несколько пакетов допустимы). В одном пакете — потолок **≤ 6 задач** (остановка набора по минутам **или** по числу задач). `estMinutes` задачи = по олимпиадному грейду (**низкий ~2**, **средний ~6**, **высокий ~12** мин); статьи ~8 мин.  
**REQ-PLN-06.** В одном пакете — разнообразие по кластеру статей (`relatedDocSlugs[0]`), по грейду (low/mid/high) и **по теме** (в режиме `mixed`), пока позволяет банк. После разнообразия скоринг предпочитает **более лёгкие** грейды (разгон от простого к сложному), а не «набор минут» за счёт high.  
**REQ-PLN-07.** Свободная работа по теме (без плана) остаётся доступной с главной.  
**REQ-PLN-08.** Переход из плана в задачу/статью и «← К плану» сохраняет вкладку (`?tab=history` / `current`), чтобы не сбрасывать контекст истории. Ссылки из плана ведут в тему элемента (`PlanItem.topicSlug`).  
**REQ-PLN-09.** У каждой задачи есть олимпиадный **грейд** `low` | `mid` | `high` (UI: низкий / средний / высокий). Это **не** `difficulty` класса (`5` / `5-6` / `6`). Грейд виден на странице задачи и в списке плана.

### 3.9 Учебная сессия и закрепление (итерация 13)

План на день (§3.8) **остаётся** как быстрый автосбор; режим «обучение/тест» **не** смешивается с формой темы плана.

| Термин | Смысл |
|--------|--------|
| Учебный пакет | `DayPlanPackage` со статусом normal и задачами; область = план (`topic:` / `mixed`) **или** ручной сбор `scopeKey=gather` |
| Пакет пройден | У **каждой** задачи пакета ≥1 верный Attempt по канону |
| Закрепление (тест) | Отдельный проход по **тем же канонам** пакета с **другими** instance |

**REQ-MODE-01.** Доступны два способа собрать **учебный** пакет: (а) план на день (§3.8); (б) **«Собрать обучение»** — ученик выбирает одну или несколько тем вручную; задачи набираются с балансом грейда и темы (тот же скоринг, что REQ-PLN-05/06), потолок ≤6 / ~60 мин.  
**REQ-MODE-02.** История пакетов ручного сбора хранится отдельно (`scopeKey=gather`), не смешивается с `topic:` / `mixed`.  
**REQ-MODE-03.** Когда учебный пакет **пройден** (все задачи верны), UI показывает CTA «Закрепить пройденный материал / тестирование по пройденному». До прохождения CTA нет (или неактивна).  
**REQ-MODE-04.** Закрепление **необязательно**; отказ — один мягкий шаг («Позже» / «Пропустить») без блокировки навигации.  
**REQ-MODE-05.** Тест включает **только** каноны **этого** учебного пакета; на каждую задачу — instance без верного Attempt по instance (пул ≥2; иначе задача в тест не входит).  
**REQ-MODE-06.** В UI и API теста **нет** подсказок, кнопки A, B, наставника, «Другой вариант», reinforce.  
**REQ-MODE-07.** В тесте на **каждый** вопрос — **ровно одна** попытка ответа: Attempt фиксируется сразу; повторная отправка того же instance запрещена; UI переходит к следующему вопросу (или итогу).  
**REQ-MODE-08.** За **завершение** теста по пакету (все вопросы отвечены) сессия закрывается. **+10 XP** и бейдж `session_reinforced` (идемпотентно на user×пакет) — **только если тест сдан** по REQ-MODE-09. Иначе итог без награды (повтор по тому же пакету недоступен). Отказ / «Позже» / «Прервать» — без награды.  
**REQ-MODE-09.** Критерий «тест сдан»: после всех ответов (REQ-MODE-07) считается `score` / `maxScore` по весам грейда верных ответов (**low=1, mid=2, high=3**). Сдан при `score ≥ ceil(0.7 × maxScore)` и `maxScore > 0`. Награда — **константа** `SESSION_REINFORCE_XP` (=10), не зависит от состава пакета. «Тема пройдена» — отдельный REQ-PRG-04 (все каноны решены), **не** по порогу баллов сессии.  
**REQ-MODE-10.** Переключатель «Обучение | Тест» на экране «Что сегодня» / в форме темы плана — **не** используется.
